# 01.4 - Seguridad y Protección de Datos

CrediLote maneja datos personales (nombre, DUI, NIT, teléfono, domicilio), datos financieros (saldos, pagos) y documentos legales firmados. Este documento describe **qué protecciones existen realmente**, qué riesgos se aceptan en la fase actual y qué reglas deben cumplirse antes de ampliar el sistema.

> [!IMPORTANT] Principio
> La documentación no promete protecciones que el sistema no implementa. Toda afirmación de esta nota debe poder verificarse en el código.

### Riesgos aceptados en la fase actual
Mientras el sistema sea **de un solo administrador, en su propio equipo y sin servicios externos de procesamiento**, se aceptan:
- almacenamiento local sin cifrado,
- ausencia de inicio de sesión en la aplicación.

**Medidas compensatorias obligatorias** para el administrador:
1. Cuenta de usuario del sistema operativo protegida con contraseña y bloqueo automático de pantalla.
2. Cifrado de disco activado (BitLocker en Windows, FileVault en macOS).
3. Un perfil de navegador dedicado a CrediLote, sin extensiones innecesarias.
4. Respaldos periódicos guardados en un lugar seguro (ver sección 4).

Estos riesgos **dejan de ser aceptables** si ocurre cualquiera de estos casos: varios usuarios, acceso desde equipos compartidos, portal para clientes o envío de documentos a un servicio externo. En ese momento se requiere backend con autenticación y se debe revisar esta nota.

## 1b. Base de datos en Neon (2026-10-01)

Ver [[ADR-013 - Persistencia en Neon Postgres y Neon Storage]].

- `DATABASE_URL` y las credenciales del bucket (`AWS_*`) están solo en `.env.local` (excluido de git) y las usa la API local. **Nunca** con prefijo `VITE_`.
- La API (`/api/estado`, `/api/documentos`) solo responde a peticiones desde este equipo y rechaza las que vienen de otros sitios. No usar `npm run dev -- --host` mientras no haya inicio de sesión.
- **Pendiente:** la contraseña de la base y la credencial del bucket se compartieron en una conversación con un agente. Cambiar la contraseña con *Reset password* y generar una credencial nueva de Storage (revocando la anterior) en Neon; luego actualizar `DATABASE_URL` y `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` en `.env.local`.
- Respaldo: cada guardado queda en `credilote_estado_historial` (últimas 300 versiones).

## 2. Servicios Externos de Extracción (IA / OCR)

**Situación:** desde [[ADR-010 - Extracción documental con Google Gemini API y conversión geodésica|ADR-010]] se usa la opción 2 (Gemini). El proxy ya está implementado; el resto de condiciones está pendiente (tarea 7.11).

Opciones en orden de preferencia para la privacidad:

1. **OCR local en el navegador** (p. ej. Tesseract.js): el documento no sale del equipo. Preferido si la precisión es suficiente.
2. **Servicio de IA externo** (p. ej. Gemini): solo con **todas** estas condiciones:
   - **Proxy propio:** la aplicación nunca llama al proveedor directamente (ver sección 3).
   - **Términos del proveedor revisados:** usar solo planes que **no** utilicen los datos para entrenar modelos y con retención limitada. Los planes gratuitos suelen permitir ese uso: no se deben usar con contratos reales.
   - **Consentimiento:** el contrato de promesa de venta, o un anexo, informa al comprador que sus datos se procesarán con herramientas automatizadas de terceros.
   - **Interruptor por proyecto:** el envío a servicios externos se puede desactivar; en ese caso se usa captura manual u OCR local.
   - **Bitácora:** se registra qué documento se envió, cuándo y a qué proveedor (sin guardar la respuesta completa fuera de la base local).
   - **Minimización:** se envían solo las páginas necesarias del contrato, no anexos ni documentos de identidad escaneados.

> [!WARNING] Marco legal a verificar
> Confirmar con asesoría legal la normativa salvadoreña vigente sobre protección de datos personales y sus obligaciones (consentimiento, transferencia a terceros fuera del país, derechos del titular). Relacionado con la decisión D4 en [[04.2 - Plan de Corrección de Documentación]].

## 3. Credenciales y Claves de API

1. **Ninguna clave de API va en el código del cliente.** Las variables `VITE_*` se incrustan en el JavaScript publicado y cualquiera puede leerlas.
2. Las claves viven solo en el **proxy**. Implementación actual: `server.proxy` de Vite (`vite.config.ts`) lee `GEMINI_API_KEY` (sin prefijo `VITE_`) y la agrega en la cabecera `x-goog-api-key`. Solo funciona con `npm run dev` o `npm run preview`; un despliegue en un servidor requerirá una función *serverless* equivalente.
3. El proxy debe:
   - aceptar solo solicitudes de la aplicación autorizada (token propio de la instalación, rotable),
   - limitar la cantidad de solicitudes por minuto y el tamaño de los archivos,
   - no guardar los documentos recibidos ni escribirlos en registros (*logs*).
4. Los archivos `.env` se excluyen del repositorio mediante `.gitignore`.

## 4. Respaldo y Restauración

Se implementa desde la **Fase 1** del roadmap (no en la Fase 5), porque los datos viven solo en el navegador.

### Exportación
- Un archivo JSON con todas las tablas del [[03.1 - Esquema de Base de Datos y Entidades|Modelo v2]]. Los `Blob` de documentos van en Base64.
- Metadatos: `schemaVersion`, versión de la aplicación, `exportedAt` y una suma de verificación SHA-256 del contenido.
- Nombre sugerido: `credilote-respaldo-AAAA-MM-DD.json`.
- **Cifrado opcional con contraseña** (Web Crypto: PBKDF2 + AES-GCM), recomendado si el archivo se guarda en la nube o en memorias USB.

### Recordatorio
- Si el último respaldo tiene más de **7 días**, la aplicación muestra un aviso persistente.
- La fecha del último respaldo se muestra en la barra lateral.

### Restauración
1. Validar la suma de verificación y `schemaVersion`. Si la versión es anterior, se aplican las migraciones; si es posterior, se rechaza.
2. Mostrar una vista previa con la cantidad de registros por tabla.
3. Crear automáticamente un respaldo del estado actual antes de restaurar.
4. **Reemplazar** todos los datos (no se combinan) tras una confirmación explícita.

### Almacenamiento persistente
Al iniciar, la aplicación solicita `navigator.storage.persist()` para que el navegador no libere la base de datos cuando le falte espacio, y muestra el resultado en la configuración.

### Custodia del respaldo
El archivo contiene datos personales: se guarda en una ubicación con acceso restringido y **nunca dentro de la carpeta del proyecto** ni en el repositorio.

## 5. Seguridad de la Aplicación

1. **No insertar HTML construido con datos del usuario.** En Leaflet, pasar a `bindTooltip` / `bindPopup` un elemento del DOM creado con `textContent`, o escapar el texto antes de usarlo. React ya escapa el contenido de JSX; no usar `dangerouslySetInnerHTML`.
2. **Validar entradas** según RN-I3 de [[03.2 - Reglas de Negocio y Cálculos]] (DUI, NIT, teléfono, montos, coordenadas).
3. **Documentos cargados:** aceptar solo `application/pdf`, `image/jpeg` e `image/png`, con tamaño máximo configurable (sugerido: 15 MB). Los PDF se muestran con un visor que no ejecuta JavaScript embebido.
4. **Integridad contable:** recibos y eventos nunca se borran, solo se anulan (invariante 6 de 03.1).
